## 0. 文档用途与审批边界

本文是原始 2,605 行愿景稿经过范围审核、外部比较、Owner 决策及最终批准后的 **P02-000 正式玩法设计基线**。它不否定原稿的长期方向，但明确区分：

1. P01 已冻结且不得重开的工程底座；
2. P02 必须完成的最小玩法内核；
3. 应移入 P03～P11 的未来系统；
4. 直接删除、不得延期复活的错误比赛模型。

Owner 已批准本文。实现线程可以据此拆分任务；但本文中的 `[CALIBRATE]` 数值仍需方向性场景校准，不能被描述成最终一年或三年平衡。

本文以 `docs/P02_GAMEPLAY_BASELINE.md` 为仓库权威版本。技术拆分、模块边界、迁移、测试和 PR/Gate 顺序由 Owner 批准后的 `docs/P02_DEVELOPMENT_PLAN.md` 规定；开发方案不得反向改写本玩法基线，获批前不启动代码。

原始愿景稿和范围审核稿只用于说明设计谱系，不是并列实现依据；其中已经被后续 Owner 决策撤销的意见，以本文为准。

### 0.2 本轮已经确认的结构性决定

| 决定        | 冻结结论                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------ |

### 0.3 对上一版审核的一项纠正

上一版审核把“完整执教时所有换人由玩家完成”误判成了与快速结算、无人操作和每周比赛直接冲突。该判断撤销。

正确关系是：

- 完整执教：不启用主动自动轮换；玩家不操作也不会阻塞比赛；
- 快速结算：使用确定性助教策略完成主动轮换；
- 所有模式：犯满、取消资格或其他强制离场必须自动补上合法阵容；
- 12 人整队的登记顺序、首发和赛前策略跨周沿用，减少重复操作。

# 1. 执行结论

## 1.1 P02 要实现什么

**[DECIDED][P02]**

P02 的玩法内核定义为：

> 在冻结的 P01 确定性、命令事务、存档、审计、时间状态机和三年生命周期上，实现“每周球队计划 + 每运营周比赛槽 + 精简球员成长 + 12 人整队/首发 + 增量比赛模拟 + 分类赛后反馈”的离线玩法闭环。

玩家每个运营周只需要完成少量决策：

1. 选择训练、恢复或一项最小球队活动；
2. 如训练，选择训练项目、强度和最多 3 名专项球员；
3. 正式赛周接受固定赛程，其他周在免费队内赛与付费友谊赛之间选择；
4. 必要时调整 12 人登记顺序、首发、场上职责和赛前战术；
5. 快速结算，或在支持的执教壳中于节间/死球换人和改战术；
6. 从赛后事实中理解训练、疲劳、默契、位置和战术如何影响比赛。

## 1.2 P02 不实现什么

**[DEFERRED]**

P02 不实现：

- 完整实时卡牌、牌库、教练费用、抽换牌、教练英雄和球员特殊牌；
- 生产级五分钟比赛 UI、2D 球场、拖拽交互和关键时刻模式；
- 29 项激活属性、13 项可调倾向、12 个多级徽章及其 XP；
- 士气、专注、压力、伤病和人物关系；
- 完整友谊赛网络、联赛、杯赛、全国赛和随机邀请；
- 正式招募、新生候选、年度补员和长期人数平衡；
- 设施、职员、传统、复杂经济和随机事件；
- 毕业纪念册、完整校史 UI、名人堂和传承；
- LLM、Agent、模型 API 或任何联网规则判定。

## 1.3 直接删除的方案

**[REMOVED]**

原稿“比赛开始时预生成全部剩余未来，任一操作后废弃并重抽全部未来”的 `FuturePlan` 方案删除，不延期。

理由：即使一个中性操作没有改变任何篮球参数，只要它使全部未来重新采样，之后的命中、失误、犯规和篮板就会被整体换成另一组随机结果。方案可以做到技术可重放，却不能公平解释“改变来自战术还是来自重新抽签”。P02 改为逐球权/片段增量 `MatchSession`，已发生历史永久提交，后续决定只改变尚未结算的判定参数。

# 2. 设计目标与玩家体验原则

## 2.1 产品定位

**[FROZEN]**

Sunny Court Manager 是中国普通高中女子篮球背景的单机球队经理游戏。玩家承担球队经理与主教练职责，核心是培养球员、安排阵容和在比赛中作教练决策，而不是经营职业俱乐部财务，也不是直接操控球员移动和投篮。

产品继续遵守：无内购、无商业抽卡、无线上竞争；允许多档位、读档、回滚和 save scumming；“成绩”只指球队成绩，不设计学习成绩系统。学校名、球队名、经理名和教练名均由玩家设置。

## 2.2 P02 体验原则

1. **每周都有篮球反馈。**96 个运营周每周都有一场正式赛、友谊赛或队内赛；24 个考试/收束周完全停赛。
2. **训练与比赛形成同周取舍。**训练先结算，高强度训练带来的成长和疲劳都会作用于本周比赛。
3. **喜欢的球员可以被持续培养。**最多 3 名专项球员由玩家明确指定，没有隐藏失败率。
4. **名单不是总评排序题。**位置覆盖、职责、疲劳、默契、倾向和对手共同决定选择，不存在“综合分最高 5 人永远正确”。
5. **战术有用但不抹平巨大实力差。**战术改变行为分布和局部执行，不直接凭空加分。
6. **失败可理解、可恢复。**疲劳会恢复，错选不会永久毁卡；无伤病、破产、永久属性倒退或隐藏橡皮筋。
7. **默认轻量，明细可展开。**普通玩家看一页结果即可继续，高阶玩家可查看真实统计和规则影响。
8. **非 LLM 本体完整。**训练、推荐、比赛、解释和档案全部由离线确定性规则完成。
9. **三年有时间压力。**核心球员会毕业，培养机会有限；毕业是阶段性情感结算，不是惩罚。

## 2.3 外部经验如何取舍

| 外部经验                                        | 对本项目的采用方式                                | 不采用部分                                   |
| ----------------------------------------------- | ------------------------------------------------- | -------------------------------------------- |
| FIBA 5 人上场、最多 12 人、4×10 分钟和 5 犯离场 | 用作正式赛/友谊赛的结构边界和强制换人规则         | 不复制全部裁判与技术犯规细节                 |
| Basketball GM 以有限分项 rating 组成球队表现    | P02 采用 10 项能力 + 静态体型代理，先验证可解释性 | 不复制职业合同、球探误差、交易和完整职业联盟 |
| WABC 训练资料将 5v5 对抗纳入训练                | 队内赛作为每周低负荷实战反馈                      | 不把现实训练计划逐分钟模拟                   |
| 女子篮球负荷研究区分训练与比赛负荷              | 训练、队内赛、友谊赛、正式赛使用不同疲劳负荷      | 不做医疗预测、伤病概率或现实生理模型         |
| 轻量体育经理允许自动推进并在关键节点干预        | 快速结算托管，完整执教在节间/死球介入             | 不引入职业经理游戏的大量日常操作             |
| 体育卡牌游戏可以让自动比赛更可参与              | 把卡牌作为 P04 的独立可玩性原型                   | 不在 P02 顺手塞入牌库、能量和实时 UI         |

# 3. 学年、学期与每周循环

## 3.1 时间结构

**[FROZEN]**

- 3 学年；
- 每学年 2 学期；
- 每学期 20 周；
- 第 1～16 周为运营周；
- 第 17～20 周为考试/收束周；
- 三年共 120 日历周、96 运营周、24 考试/收束周。

## 3.2 一个运营周的确定顺序

**[DECIDED][P02]**

```text
周开始：读取已在“进入本周”时提交的自然恢复，查看赛程与状态
  ↓
选择一个球队计划
  ├─ 标准/集中训练
  ├─ 恢复
  └─ 最小球队活动
  ↓
若为训练：选择项目，并指定 0～3 名专项球员
  ↓
确定比赛槽
  ├─ 已排正式赛：不可替换
  ├─ 默认队内赛：免费
  └─ 邀请友谊赛：付费替换队内赛
  ↓
结算球队计划：成长、默契经验、经费和赛前疲劳
  ↓
锁定比赛输入：正式/友谊赛锁定 12 人，队内赛锁定蓝白分组；同时锁定首发、职责和基础战术
  ↓
进行比赛：快速结算或执教壳
  ↓
分类结算比赛、学习、疲劳、默契、声誉和档案
  ↓
推进至下一周
```

球队计划与比赛槽是并存关系：球队活动只替代训练，不替代比赛；一周恰好一个比赛槽，不会同时进行队内赛和友谊赛。

## 3.3 每周玩家操作量

| 决策               |     是否每周强制 |          典型操作 |
| ------------------ | ---------------: | ----------------: |
| 选择球队计划       |               是 |              1 次 |
| 选择训练项目与强度 |         仅训练周 |              2 次 |
| 指定专项球员       |             可选 |           0～3 次 |
| 队内赛改为友谊赛   | 可选、非正式赛周 |           0～1 次 |
| 调整登记顺序/首发  |       仅玩家想改 | 0～数次，跨周沿用 |
| 赛前战术与职责     |         默认沿用 |           0～3 次 |
| 临场换人/战术      |   仅选择完整执教 |         0～若干次 |

普通玩家使用沿用设置和快速结算时，每周只需 2～4 个核心操作。

## 3.4 每学期比赛节奏

**[P02]**

P02 暂沿用“每第 4 个运营周一场正式赛”的固定占位赛程：

| 学期运营周 | 比赛槽                     |
| ---------- | -------------------------- |
| 1～3       | 队内赛，或付费替换为友谊赛 |
| 4          | 正式赛                     |
| 5～7       | 队内赛，或付费替换为友谊赛 |
| 8          | 正式赛                     |
| 9～11      | 队内赛，或付费替换为友谊赛 |
| 12         | 正式赛                     |
| 13～15     | 队内赛，或付费替换为友谊赛 |
| 16         | 正式赛                     |
| 17～20     | 无球员活动、无比赛         |

因此每学年有 8 场正式赛和 24 个队内赛/友谊赛槽；三年有 24 场正式赛和 72 个队内赛/友谊赛槽。完整赛事结构属于 P06，该固定节奏只为 P02 建立闭环和验证三年状态机。

## 3.5 考试/收束周

**[DECIDED]**

考试/收束周没有任何球员活动：

- 不训练；
- 不选择“恢复训练”；
- 不进行队内赛、友谊赛或正式赛；
- 不举办球队活动；
- 不产生训练 XP、实战 XP 或默契活动经验；
- 只执行时间推进、疲劳自然恢复、学期总结、年度拨款、年级推进、毕业和归档。

自然恢复是状态随休息时间变化，不被视为球员活动。P02 初始值为每个考试周疲劳 `-15`，下限 0。[CALIBRATE]

自然恢复采用明确的“进入周”语义：完成前一周并推进日历的同一原子事务，在建立下一周后立即提交下一周的自然恢复；新游戏第 1 周被视为已处于周首恢复后的初始状态，不额外重复恢复。因此，玩家在当前周保存计划、开始比赛或中止比赛，都不会再次触发或回滚本周已经生效的自然恢复。

# 4. 三种比赛槽及其结算边界

## 4.1 类型规则

| 类型               | 产生方式                 | 默认体验           | 主要收益                                 | 代价         | 战绩与档案                     |
| ------------------ | ------------------------ | ------------------ | ---------------------------------------- | ------------ | ------------------------------ |
| 正式赛 `OFFICIAL`  | 固定赛程                 | 玩家可选快速或执教 | 正式成绩、完整统计、声誉、较高实战学习   | 高疲劳       | 计入正式胜负与正式生涯         |
| 友谊赛 `FRIENDLY`  | 付费替换非正式周的队内赛 | 快速或执教         | 对手检验、实战学习、首次成绩带来少量声誉 | 中疲劳、经费 | 单独记录，不污染正式胜负       |
| 队内赛 `SCRIMMAGE` | 非正式周默认             | P02 固定快速       | 观察阵容、替补成长、个人默契             | 低疲劳       | 仅摘要，不计正式战绩和正式生涯 |

三类比赛必须具有 `matchKind` 和独立的 `recordScope`。禁止像 P01 一样把所有 `matchResults` 直接累计为球队正式胜负或毕业正式比赛数。

## 4.2 队内赛具体规则

**[P02]**

- 复用同一 5v5 比赛引擎，不另建 3v3、4v4 或简化“掷骰子结果”模型；
- 与正式赛共用 4×10 分钟和同一球权规则，但使用更低负荷系数；不打加时，平局允许；
- 全部活跃球员由系统确定性均衡分成蓝、白两队，两边均采用深轮换助教策略；
- 分组先按主位置分桶；每个位置桶内按该位置相关能力摘要降序排列。逐人分配时，依次选择该位置人数更少、该位置能力合计更低、全队人数更少、全队能力合计更低的一方；仍并列时先蓝队。球员排序并列按稳定球员 ID；
- 分组只用于本周队内赛，不保存“固定蓝队/白队”，也不形成组合默契；
- 当前 P02 固定 12 人，分组结果为蓝、白各 6 人，双方各有 5 名首发和 1 名替补；未来招募、毕业补员和人数不足处理由 P03 阵容续航规则解决；
- 所有参与者可获得低量实战学习和默契经验；
- 只保存比分、出场、关键能力观察和成长摘要；不写入正式胜负、正式生涯累计或声誉。
- P02 不让玩家临场执教蓝队或白队；队内赛固定快速结算，避免每周增加一场必须选择执教立场的比赛。未来若需要训练赛实验模式，另行进入 P05。

队内赛的目的不是让玩家每周看一场完整比赛，而是把“训练后的阵容反馈”稳定送回玩家。

## 4.3 友谊赛具体规则

**[P02]**

- 非正式赛周可在球队计划结算前发出邀请；
- 邀请成功没有随机概率，满足声誉门槛并支付经费即可；
- 对手来自固定的同档/较强/强校三档模板；
- 每个稳定 `opponentId` 的首次胜利声誉只奖励一次；同档位的不同对手分别判断，重复战胜同一对手不再奖励；
- 比赛结构为 4×10 分钟，平局进入 5 分钟加时，直至分出胜负；
- 友谊赛统计单独保存，可用于玩家分析和实战学习，但不计正式战绩。
- 友谊赛登记整支 12 人球队；它替代本周免费队内赛，机会成本是邀请经费、更高比赛负荷，以及失去低负荷队内观察赛。

## 4.4 正式赛具体规则

**[P02]**

- 比赛结构采用 4×10 分钟；
- 每名球员 5 次犯规后强制离场；
- 平局进行 5 分钟加时，直至分出胜负；
- 12 人名单在开赛时锁定；
- 只有正式赛更新球队正式胜负、竞技纪录和正式生涯统计；
- P02 不设计排名、淘汰赛和全国赛，只在比赛记录中保留通用的赛程来源引用；不提前冻结未来赛事系统的字段名或结构。

## 4.5 三类比赛的负荷初值

比赛疲劳随每个已提交时间片逐步增加，因而会影响之后的球权和助教轮换。不得在终场按整场分钟倒算，也不得把加时封顶在 40 分钟：

```text
耐力修正 = 1 - 0.003 × 耐力
本时间片疲劳增加 = 类型基础负荷 × (本时间片在场秒数 / 2400)
                   × 耐力修正 × 当前节奏负荷系数
                   × 当前防守策略负荷系数
```

每次提交球权或罚球时间片后按当时在场球员累计；加时继续累加，没有 `min(1)`。防守策略负荷只在该球员所在球队防守的时间片生效。终场疲劳必须等于所有已提交时间片增量之和。

耐力修正范围自然落在 `0.70～1.00`。

| 比赛类型 | 类型基础负荷 [CALIBRATE] |
| -------- | -----------------------: |
| 队内赛   |                        6 |
| 友谊赛   |                       10 |
| 正式赛   |                       12 |

节奏负荷系数为慢 `0.90`、平衡 `1.00`、快 `1.15`；防守策略负荷系数默认为 `1.00`，外扩压迫为 `1.10`。两者相乘后的总战术负荷系数限制在 `0.85～1.20`。[CALIBRATE]

训练负荷和比赛负荷分别记录于本周结算，以便玩家知道疲劳来自哪里。

# 5. P02 球员模型

## 5.1 模型总览

**[P02]**

每名球员在 P02 只包含会影响真实选择或反馈的层次：

1. 身份、年级和星级；
2. 主位置与最多一个副位置；
3. 10 项可训练能力；
4. 一个不可训练的体型/臂展代理；
5. 6 个固定行为倾向；
6. 0～1 个固定原型特质；
7. 疲劳；
8. 个人默契；
9. 每项能力 XP、软上限和生涯统计。

P02 不把士气、专注、压力、伤病、关系矩阵、总成长容量或徽章 XP 放入玩法状态。P01 的同名占位字段只由回归适配器处理，不作为 P02 新内容语义。

## 5.2 星级边界

| 星级  | P02 处理                                               |
| ----- | ------------------------------------------------------ |
| 2★    | P01 工程夹具，不进入 P02 正式内容                      |
| 3★    | 通用角色主体，提供阵容厚度和明确专长，软上限较低       |
| 4★    | 独立角色和主要培养核心，软上限较高，可拥有一个原型特质 |
| 5★/6★ | 不生成、不平衡；突破、统治能力和稀有度体验移入 P09     |

星级在 P02 只影响内容身份、能力初始区间、每项软上限和是否拥有原型特质。它不直接在比赛公式中提供隐藏加成。

## 5.3 十项可训练能力

能力均使用公开的 `0～100` 整数值。

| 能力     | 回答的问题                 | 主要比赛作用                        |
| -------- | -------------------------- | ----------------------------------- |
| 终结     | 能否在篮下和对抗中完成进攻 | 上篮、近框、造犯规后的完成质量      |
| 投射     | 能否稳定完成中远距离和罚球 | 中投、三分、罚球                    |
| 控球     | 能否持球推进并保护球       | 突破准备、压迫下失误、持球稳定      |
| 组织     | 能否发现并创造队友机会     | 传球、助攻、空位创造                |
| 外线防守 | 能否限制持球人和外线出手   | 外线干扰、突破第一道防线            |
| 内线防守 | 能否守护禁区               | 篮下干扰、护框、低位防守            |
| 篮板     | 能否争抢和控制篮板         | 进攻/防守篮板                       |
| 运动能力 | 速度、敏捷、爆发的合并代理 | 转换、协防、对抗到位和二次起跳      |
| 耐力     | 能否承受训练与比赛负荷     | 疲劳增长速度，不直接加命中          |
| 战术理解 | 能否稳定执行团队要求       | 传切、轮转、战术变更和持球/传球错误 |

选择 10 项而不是 29 项的依据：P02 要先证明训练、阵容和比赛闭环可解释。29 项会同时放大内容制作、成长曲线、训练 UI、比赛公式和赛后说明的组合空间，却尚无原型证据证明玩家需要区分“空位终结/对抗终结/受干扰终结”等全部细项。完整 29 项词典保留为 P08 的必要性评估输入，不提前锁入存档。

## 5.4 静态体型/臂展代理

每名球员保留展示用身高，并由身高、臂展和站立摸高内容定义得到一个 `体型影响` 值 `0～100`：

- 不可通过训练改变；
- 参与篮下终结、内线防守、篮板和封盖判定；
- 不单独决定位置；
- 不直接计入一个“综合总评”；
- P02 不模拟青春期身高增长。

## 5.5 位置与位置适配

采用 PG、SG、SF、PF、C 五位置。每名球员有一个主位置和最多一个副位置。任何球员都可被放入任意场上位置，不设硬锁。

| 位置关系 | 显示适配度 | 对比赛的唯一额外作用     |
| -------- | ---------: | ------------------------ |
| 主位置   |       100% | 无额外修正               |
| 副位置   |        95% | 相关职责判定 `-3` 执行点 |
| 其他位置 |        85% | 相关职责判定 `-8` 执行点 |

显示适配度不再作为乘数进入公式；上表执行点是位置错配的唯一额外修正。它只作用于组织职责、防守对位、战术站位和协作判定，不降低该球员的原始投射或终结能力。惩罚有上限，避免位置错配导致比赛非法。

## 5.6 场上角色

角色标签是由能力、倾向和特质生成的可读摘要，例如：

- 第一组织者；
- 射手；
- 突破手；
- 3D 侧翼；
- 防守指挥者；
- 护框者；
- 篮板手；
- 策应内线。

角色本身不加数值、不拥有第二套 XP，也不强制球员只能做一种行为。能力或倾向变化后，摘要标签可以重算。

用于队内赛分组、系统推荐和替补候选排序的“位置相关能力摘要”只作确定性工具，不进入比赛公式：[CALIBRATE]

| 位置 | 摘要权重                                                     |
| ---- | ------------------------------------------------------------ |
| PG   | 控球 30%、组织 35%、投射 15%、外线防守 10%、战术理解 10%     |
| SG   | 投射 35%、终结 20%、控球 15%、外线防守 15%、运动能力 15%     |
| SF   | 投射 20%、终结 20%、外线防守 20%、运动能力 20%、篮板 20%     |
| PF   | 终结 20%、内线防守 25%、篮板 25%、运动能力 15%、投射 15%     |
| C    | 内线防守 25%、篮板 30%、体型影响 20%、终结 15%、战术理解 10% |

该摘要不向玩家宣称“真实总评”，也不能替代职责和战术判断。

## 5.7 六个固定行为倾向

P02 保留足以生成不同打法的 6 个行为概念，不提供 13 个逐项训练滑杆：

| 倾向     | 作用                                              |
| -------- | ------------------------------------------------- |
| 球权参与 | 获得和保留球权的相对权重                          |
| 传球选择 | 持球后寻找队友而非自行终结的相对权重              |
| 出手区域 | 外线/中距离/篮下的归一化偏好向量                  |
| 转换参与 | 快攻推进、跟进和提前落位的权重                    |
| 防守冒险 | 抢断、协防和压迫的主动程度，同时影响失位/犯规风险 |
| 前场篮板 | 投篮后冲抢而非优先退防的权重                      |

除“出手区域”外，五个倾向都是公开的 `0～100` 固定值；出手区域是 `{外线, 中投, 篮下}` 三个非负整数，合计必须为 `100`。它们在 P02 不通过训练变化。

引擎先过滤当前球权中的合法行为，再按下式归一化抽取：

```text
行为权重 = 内容倾向权重 × 战术倍率 × 场景可用性
```

- `场景可用性` 范围 `0～1`；不合法行为为 `0`，时钟、站位和防守压力只改变可用性；
- 球权参与用于选择持球者；传球选择以 `传球选择` 对 `100-传球选择` 比较传球与自行处理；
- 转换参与、防守冒险、前场篮板分别与各自的 `100-倾向值` 比较转换/落位、冒险/稳守、冲抢/退防；
- 进入投篮分支后直接使用三元出手区域向量；
- 若过滤后的总权重为 `0`，使用固定安全行为：按与持球者场上位置槽的序号距离、默认名单顺序、稳定球员 ID 选择第一名合法队友传球；无合法传球时执行当前区域最低风险的合法出手。行为并列按固定行为顺序打破，不依赖未建模的空间距离。

倾向不直接改变成功率；它只决定球员更可能选择什么。内容模板同时公开数值和一句风格摘要。完整倾向培养和人物驱动变化移入 P08/P10。

## 5.8 六个固定原型特质

P02 只需验证“场景专长是否有价值”，不建立徽章等级、装备槽或进度系统。每名球员最多拥有 1 个固定特质；3★可以没有，4★夹具固定拥有 1 个，以保证 4★在 P02 已有明确内容价值：

| 特质     | 唯一生效场景           | 初始效果 [CALIBRATE] |
| -------- | ---------------------- | -------------------: |
| 定点射手 | 获得空位外线出手时     |        投射执行 `+6` |
| 强硬终结 | 篮下对抗终结时         |        终结执行 `+6` |
| 稳健持球 | 持球/传球失误判定时    |        控球执行 `+6` |
| 外线锁防 | 直接防守持球人时       |    外线防守执行 `+6` |
| 禁区屏障 | 篮下干扰/封盖判定时    |    内线防守执行 `+6` |
| 篮板嗅觉 | 有对抗的篮板归属判定时 |        篮板执行 `+6` |

特质获得即生效，无等级、无 XP、无装备选择。赛后只有实际进入对应场景时才记录触发。完整徽章、多级颜色、获得条件和传承移入 P08/P09。

# 6. 疲劳与个人默契

## 6.1 P02 只激活两个动态状态

**[DECIDED][P02]**

- `疲劳`：连接训练强度、比赛出场、恢复、轮换和临场表现；
- `个人默契`：连接共同训练、共同比赛、阵容稳定和团队执行。

士气、专注、压力没有 P02 规则，因此不作为 P02 玩家状态显示，也不在新比赛公式中保持“固定 50”的伪状态。它们在人物系统明确来源、决策和反馈前不得启用。

## 6.2 疲劳规则

疲劳范围 `0～100`，数值越高状态越差。

每个运营周开始，所有活跃球员先自然恢复 `10` 点；每个考试/收束周自然恢复 `15` 点。[CALIBRATE]

比赛中的能力惩罚：

```text
疲劳执行惩罚 = clamp((疲劳 - 30) × 0.20, 0, 14)
```

- 终结、投射、控球、外线防守、内线防守、篮板、运动能力扣除完整惩罚；
- 组织和战术理解扣除一半惩罚；
- 耐力不被扣除，它只降低之后的负荷增长；
- 疲劳不触发伤病、永久下降或强制禁赛。

训练效率：

```text
疲劳训练效率 = 1 - clamp((训练前疲劳 - 50) × 0.005, 0, 0.25)
```

高疲劳最多使本周训练 XP 降至正常的 75%，不会让训练失败或倒扣能力。

## 6.3 个人默契数据

每名球员只保存一个公开的 `个人默契`，范围 `0～100`：

- 表示她对本队训练语言、战术要求和协作节奏的熟悉程度；
- 不保存球员两两关系；
- 不保存任何固定五人组合；
- 不把历史共同出场次数作为独立能力；
- 当前场上默契是即时派生值，不写入长期存档。

P02 新内容初值：[CALIBRATE]

| 年级 | 初始个人默契 |
| ---- | -----------: |
| 高一 |           45 |
| 高二 |           60 |
| 高三 |           75 |

## 6.4 当前五人即时加权

```text
场上默契 C = Σ(个人默契 Fi × 当前职责权重 Wi) / ΣWi
```

| 当前职责     | 权重 |
| ------------ | ---: |
| 第一组织者   | 1.25 |
| 进攻战术枢纽 | 1.10 |
| 防守指挥者   | 1.10 |
| 其他球员     | 1.00 |

同一球员承担多个职责时只取最高权重，不叠加。

正常比赛对当前五人计算；极端犯满导致短人时，对实际仍在场的 2～4 人使用同一公式，分母始终是实际职责权重之和。

系统在以下节点重新计算：

- 比赛开始；
- 换人正式生效；
- 犯满等强制替换；
- 玩家改变场上职责；
- 战术调整更换第一组织者或战术枢纽。

位置适配和战术适配是独立机制，不乘入默契公式，避免同一问题被重复惩罚。

## 6.5 默契对比赛的作用

```text
团队执行修正 = clamp((C - 50) × 0.12, -6, +6)
```

只作用于团队协作判定：

- 传球衔接和持球/传球失误；
- 无球跑动和由配合创造的空位质量；
- 协防、轮转和换防；
- 新战术指令的执行稳定性。

不直接增加个人投篮、罚球、力量、速度、单人篮板或一对一防守能力。因此高默契能让球队更顺畅，但不能抹平明显能力差距。

## 6.6 默契成长

每次配合经验使用同一更新函数：

```text
应用配合经验(F, E) = F + (100 - F) × E / 100
```

本节与实战 XP 使用 `成长出场比例 = min(1, 实际出场秒数 / 2400)`；它只封顶学习收益，不参与比赛疲劳，加时仍会继续增加疲劳。

| 来源         |  配合经验 [CALIBRATE] |
| ------------ | --------------------: |
| 普通团队训练 |                  +0.5 |
| 配合演练训练 |                  +2.0 |
| 球队聚餐     |                  +3.0 |
| 校内公开训练 |                  +0.5 |
| 队内赛       | `+2.0 × 成长出场比例` |
| 友谊赛       | `+1.5 × 成长出场比例` |
| 正式赛       | `+1.5 × 成长出场比例` |
| 考试/收束周  |                     0 |

训练或球队活动产生的配合经验在赛前计划结算时应用，因此配合演练和聚餐会影响本周比赛；比赛产生的配合经验在赛后按实际成长出场比例应用。两阶段使用更新后的值依次结算，不把全周经验先相加，也不回改已经完成的比赛判定。

P02 不设置个人默契自然衰减。新人较低、老生较高和毕业更替已经提供时间压力。

# 7. 训练、恢复与成长

## 7.1 每周球队计划

每个运营周恰好选择一个：

1. 标准训练；
2. 集中训练；
3. 恢复；
4. 球队聚餐；
5. 校内公开训练。

第 4、5 项是 P02 唯一的最小球队活动，不建立随机事件、活动商店或内容池。

## 7.2 训练项目

选择标准或集中训练时，再选择一个训练项目：

| 项目       | 主收益         | 关联收益           | 其他作用               |
| ---------- | -------------- | ------------------ | ---------------------- |
| 外线进攻   | 投射           | 组织、战术理解     | 形成外线打法基础       |
| 突破终结   | 终结、控球     | 运动能力           | 提升篮下创造和完成     |
| 传切组织   | 组织           | 控球、战术理解     | 提升传球衔接           |
| 外线防守   | 外线防守       | 运动能力、战术理解 | 提升压迫与轮转         |
| 内线与篮板 | 内线防守、篮板 | 耐力               | 提升禁区和回合结束能力 |
| 转换体能   | 运动能力、耐力 | 控球               | 提升快攻与负荷承受     |
| 配合演练   | 战术理解       | 少量组织           | 主要获得个人默契经验   |

## 7.3 训练 XP 初值

能力拥有独立 XP。升级需求：

```text
升到下一点所需 XP = 100 + 5 × 当前能力值
```

标准训练基础收益：[CALIBRATE]

- 单主收益项目：主能力 `+24 XP`；
- 双主收益项目：两项各 `+18 XP`；
- 关联能力：每项 `+10 XP`；
- 微量辅助：`+4 XP`；
- 集中训练将本训练项目的全部 XP（包括配合演练的 `+12/+4`）乘以 `1.35`；
- 再乘疲劳训练效率和软上限效率。

配合演练的标准强度基值为战术理解 `+12 XP`、组织 `+4 XP`，并按第 6.6 节增加默契；集中强度仍按上条乘数处理。它主动放弃一次高额专项能力训练，是明确取舍。

同一结算阶段内，先按“该阶段开始时”的能力、软上限和疲劳快照计算每项能力的全部 XP，再同时加入 XP 池。若 XP 达到升级阈值，则反复扣除当前阈值并逐点升级，保留剩余 XP；达到能力 100 后不再升级。训练结算完成后的能力用于本周比赛，比赛 XP 则以赛前成长后的能力为起点在赛后结算。

## 7.4 专项培养

标准或集中训练后，玩家可指定 0～3 名球员，每人选择一项具体能力：

- 目标能力额外 `+20 XP`；
- 额外训练疲劳基础值 `+2 × 耐力修正`；
- 同一球员一周只能获得一次专项；
- 系统不能自动替玩家分配专项名额；
- 不存在随机失败或永久副作用。

专项 XP 同样受疲劳效率和软上限效率影响。

## 7.5 软上限

每名球员的每项能力有公开软上限：

- 能力低于软上限：XP 效率 `1.00`；
- 能力达到或超过软上限：XP 效率 `0.35`；
- 软上限不是硬锁，玩家仍可逆模板培养，只是成本更高；
- 3★整体软上限区间低于 4★；
- P02 不再叠加“总成长容量”，避免两个系统同时限制同一件事。

具体软上限分布由 P02 固定球员夹具提供，正式星级生成规则属于 P03。

## 7.6 训练负荷

```text
耐力修正 = 1 - 0.003 × 耐力
训练疲劳增加 = 强度基础负荷 × 耐力修正
```

| 计划         | 能力成长 | 疲劳变化 [CALIBRATE] | 其他                   |
| ------------ | -------- | -------------------: | ---------------------- |
| 标准训练     | 1.00 倍  |      `+8 × 耐力修正` | 普通训练默契经验       |
| 集中训练     | 1.35 倍  |     `+14 × 耐力修正` | 同周比赛状态更差       |
| 恢复         | 0        |                `-18` | 不产生训练 XP          |
| 球队聚餐     | 0        |                 `-6` | 花经费、较高默契经验   |
| 校内公开训练 | 0        |      `+2 × 耐力修正` | 花经费、少量默契与声誉 |

本周顺序是“自然恢复 → 训练/活动 → 比赛”。因此集中训练可以在本周提升能力，也会立刻增加赛前疲劳；玩家在正式赛周必须决定是否冲成长。

## 7.7 实战学习

比赛不直接随机涨一大串属性。按第 6.6 节的成长出场比例给予小额、可解释的学习：[CALIBRATE]

| 类型   |         战术理解 XP | 本场使用最多的相关能力 XP |
| ------ | ------------------: | ------------------------: |
| 队内赛 |  `6 × 成长出场比例` |        `3 × 成长出场比例` |
| 友谊赛 | `10 × 成长出场比例` |        `5 × 成长出场比例` |
| 正式赛 | `12 × 成长出场比例` |        `6 × 成长出场比例` |

“使用最多的相关能力”由实际统计确定，例如外线出手、篮下终结、助攻创造、外线对位、内线干扰或篮板，不由叙事文本猜测。单场只奖励一项，避免刷数据造成不可控成长。

确定映射为：外线/中投出手次数→投射，篮下出手→终结，持球推进回合→控球，创造投篮的传球→组织，外线直接对位回合→外线防守，篮下直接对位回合→内线防守，篮板争抢→篮板，转换参与→运动能力。取计数最高项；并列按本表顺序。耐力和战术理解不参加该“使用最多”竞争，耐力只通过训练成长，战术理解已获得固定实战 XP。

## 7.8 每周成长反馈

结算页必须显示：

- 每名球员各能力获得 XP；
- 哪部分来自团队训练、专项和比赛；
- 软上限造成的效率变化；
- 训练疲劳、比赛疲劳和自然恢复；
- 个人默契本周经验与新值；
- 本周是否升级及升级前后数值。

禁止只显示“训练效果很好/一般”而不展示实际变化。

# 8. 12 人球队：登记顺序、首发、职责与轮换

## 8.1 12 人整队登记

**[DECIDED][P02]**

- P02 球队必须恰好有 12 名活跃球员；正式赛和友谊赛登记全部 12 人，不提供排除队员的二次名单选择；
- 玩家维护 12 人的稳定登记顺序，用于轮换候选和所有并列决胜；登记顺序跨周沿用；
- 队内赛同样使用全部 12 名活跃球员，按第 4.2 节规则确定性均衡分为蓝、白各 6 人；
- 登记中的球员必须活跃且 ID 唯一，并且与当前活跃球员集合完全相等；
- P02 不以位置覆盖作为合法性硬锁，但会给出明确警告；
- P02 固定内容夹具为 12 名高一球员，三年内不会发生中途毕业；P03 接入招募和混合年级后，毕业产生的空位必须先补到 12 人，才能开始正式赛或友谊赛。

## 8.2 系统推荐

推荐是确定性规则，不是 LLM，也不直接覆盖玩家设置。由于整支球队均已登记，它只建议登记顺序、首发、职责和轮换优先级，不筛除球员。建议按以下顺序构造：

1. 至少保留一名可承担第一组织者的球员；
2. 至少保留两名可承担内线位置的球员；
3. 覆盖 PG/SG/SF/PF/C 五个首发槽位；
4. 对每个首发职责保留至少一个替补候选；
5. 在覆盖相同的候选中优先低疲劳、较高位置适配和较高相关能力；
6. 最后才参考综合能力摘要，绝不把总评排序当作首发或轮换的唯一答案。

每项建议必须给理由，例如“当前名单只有一名可靠持球者”“两名内线疲劳均高于 70”“对手篮板强，建议加入第二篮板手”。

## 8.3 首发与场上职责

玩家设置首发 5 人并为五个场上位置指定球员。赛前可指定：

- 第一组织者；
- 进攻战术枢纽；
- 防守指挥者。

如玩家未指定，系统依次按组织/控球、组织/战术理解、内外线防守/战术理解确定默认人选；同分按默认名单顺序。职责用于球权、战术执行和默契加权，不是无条件属性加成。

每次换人或强制离场生效后，若某项职责的持有人已不在场，系统立即按上句的同一确定性排序，在当前五人中补派该职责；完整执教玩家可在同一个合法死球边界覆盖补派结果。职责不允许悬空，也不允许指向场下球员，随后立即重算场上默契。

## 8.4 完整执教模式

**[DECIDED]**

- 所有非强制换人由玩家排队；
- 不设置自动分钟表、位置第一替补或主动自动轮换；
- 玩家不操作时比赛继续推进，首发可以一直留场，代价由疲劳真实体现；
- 换人只在死球或节间生效；
- 玩家可以在生效前取消等待换人；
- 多人换人可在同一死球一次提交；
- P02 只冻结领域规则和调试壳，拖拽交互属于 P05。

## 8.5 快速结算的确定性助教轮换

快速结算必须选择一个助教预设，默认“平衡”：

| 预设   | 最多主动使用人数 | 连续出场检查 | 疲劳换人阈值 [CALIBRATE] |
| ------ | ---------------: | -----------: | -----------------------: |
| 浅轮换 |                8 |      10 分钟 |                       75 |
| 平衡   |               10 |       8 分钟 |                       65 |
| 深轮换 |               12 |       6 分钟 |                       55 |

在每次死球和节间，助教按以下固定顺序检查：

1. 犯满或取消资格必须立即换下；
2. 达到本预设疲劳阈值；
3. 达到连续出场分钟；
4. 同时多人满足时，优先疲劳最高者；
5. 替补候选按“目标位置适配 → 当前疲劳更低 → 第 5.6 节目标位置能力摘要更高 → 默认名单顺序”选择；
6. 换人后仍尽量保留一名第一组织者和一名内线防守者；找不到时允许位置错配并记录警告。

主动轮换池固定为首发 5 人，加默认名单顺序最前的 3/5/7 名合资格替补，分别对应浅/平衡/深轮换。疲劳触发时，候选替补必须至少比被换下球员低 5 点疲劳；连续出场触发可以放宽该条件。新上场球员至少完成 2 个比赛分钟后才可因主动策略再次被换下，避免每个死球来回互换。犯满、取消资格、人数不足等强制替换不受主动池、5 点差或最短轮换段限制。职责持有人离场后按第 8.3 节立即补派。

快速结算没有随机“教练灵感”。同一输入、seed 和预设必须产生同一换人记录。

## 8.6 强制离场兜底

- 正式赛和友谊赛采用 5 犯离场；
- 完整执教模式也不能等待玩家为犯满球员手动换人；
- 固定兜底选择规则与助教候选排序相同；
- 若已无替补则允许以不足 5 人继续；少于 2 名合资格球员时，正式/友谊赛以规则性失败结束并记录原因，队内赛提前结束；
- P02 无伤病，所以正常 12 人名单下该边界只用于完整性测试。

# 9. 最小经费与声誉闭环

## 9.1 只保留两种学校资源

**[P02]**

## 9.2 经费单位与拨款

P02 使用抽象“经费点”，不向玩家展示虚假的精确人民币账本。

年度拨款发生的周次属于 P01 冻结事实；`G` 的最终大小属于 P06 平衡，不影响 P02 机制结构。

# 10. 赛前准备与战术

## 10.1 赛前必须冻结的输入

正式赛和友谊赛开赛前建立不可变的 `MatchInput` 快照，至少包含：

- 比赛类型、赛制和对手；
- 双方可用名单与首发；
- 五个场上位置；
- 第一组织者、进攻枢纽和防守指挥者；
- 球员能力、体型、倾向、特质、疲劳和个人默契；
- 基础节奏、进攻重心和防守重心；
- 快速结算时的助教轮换预设；
- 内容版本、规则版本和比赛局部 seed。

队内赛使用同一输入结构，但名单由确定性分组器生成。

## 10.2 三个基础战术轴

### 节奏

| 选择 | 球权与行为                             | 代价 [CALIBRATE]                                       |
| ---- | -------------------------------------- | ------------------------------------------------------ |
| 慢   | 平均回合时长 `×1.12`，转换权重 `×0.80` | 追分能力较弱，失误率按第 12.4 节降低，比赛负荷 `×0.90` |
| 平衡 | 基准                                   | 基准                                                   |
| 快   | 平均回合时长 `×0.88`，转换权重 `×1.25` | 失误率按第 12.4 节提高，比赛负荷 `×1.15`               |

### 进攻重心

| 选择 | 行为权重 [CALIBRATE]                                   | 适合                      | 风险               |
| ---- | ------------------------------------------------------ | ------------------------- | ------------------ |
| 外线 | 外线出手 `×1.25`、篮下出手 `×0.85`                     | 投射和组织较强、对方收缩  | 投射不足时浪费回合 |
| 均衡 | 基准                                                   | 不确定对手或阵容均衡      | 没有针对性优势     |
| 篮下 | 篮下行为 `×1.25`、外线出手 `×0.85`、造犯规权重 `×1.10` | 终结/体型优势、对方内防弱 | 遭收缩时空间变差   |

### 防守重心

| 选择     | 防守修正 [CALIBRATE]                                 | 明确代价                                      |
| -------- | ---------------------------------------------------- | --------------------------------------------- |
| 外扩压迫 | 对方外线出手执行 `-4`，失误公式中的防守压力执行 `+4` | 对方突破和篮下机会质量 `+3`，防守负荷 `×1.10` |
| 均衡     | 基准                                                 | 无针对性优势                                  |
| 收缩禁区 | 对方篮下执行 `-4`，本方防守篮板执行 `+2`             | 对方外线机会质量 `+3`                         |

三个战术轴分别改变节奏、行为分布和对抗环境，不直接写入“本队得分 +N”。

## 10.3 防止固定答案

P02 使用以下硬规则防止万能战术：

1. 每个战术同时有收益和代价；
2. 战术只影响对应场景，不能无条件提高全队所有能力；
3. 单个战术轴对一次判定的净执行修正上限为 `±6`；
4. 球员能力、疲劳和位置仍先于战术决定执行基础；
5. 对手拥有公开的阵容特点和可解释策略；
6. 战术效果通过实际出手、失误、篮板和机会质量反馈，而非隐藏胜率；
7. 明显强弱队的能力差不能被一个正确战术稳定抹平。

## 10.4 战术适配提示

赛前系统只能给事实和风险，不给“唯一最优答案”。示例：

> 对手内线防守较弱，但你的首发终结能力一般；强攻篮下有对位收益，也可能降低整体进攻效率。

> 当前阵容只有一名可靠持球者，快节奏将提高她的使用和疲劳压力。

提示由确定性规则生成，并列出使用的能力、位置、疲劳和对手信息。

# 11. 比赛中的玩家控制

## 11.1 P02 的两种控制策略

| 策略                  | 玩家介入                  | 主动轮换   | P02 交付           |
| --------------------- | ------------------------- | ---------- | ------------------ |
| 快速结算 `INSTANT`    | 赛前设置后直接完成        | 确定性助教 | 完整 headless 能力 |
| 完整执教 `FULL_COACH` | 节间/死球改战术、排队换人 | 玩家手动   | 领域规则与调试壳   |

正式赛和友谊赛可选择上述两种控制策略；队内赛在 P02 固定快速结算。`KEY_MOMENTS`、五分钟生产播放、暂停界面和 2D/拨片表现移入 P04/P05，不作为 P02 Gate。

## 11.2 最小临场调整

完整执教时，玩家只能在节间或死球提交：

- 改变节奏；
- 改变进攻重心；
- 改变防守重心；
- 改变第一组织者、进攻枢纽或防守指挥者；
- 排队一个或多个换人；
- 取消尚未生效的排队换人。

战术命令在当前合法控制边界提交，在恢复活球后的下一个比赛片段开始时生效；换人在该死球结束、下一片段开始前一次性生效。即使球权归属未改变，普通犯规或出界后的下一片段也使用新阵容和新战术。现实墙钟、动画帧率和玩家点击速度都不是规则输入。

临场改战术不消耗“教练能量”，也不重新抽随机数。新战术从恢复活球后的下一比赛片段起完整替换旧值，持续到下一次合法调整；相同值重复提交返回 `NO_CHANGE`，不写 transcript，也不产生、延长或叠加修正。玩家可以反复调整，但每次只改变之后的篮球参数，不能通过重复提交刷未来结果。

## 11.3 通用比赛效果接口

**[DECIDED][P02]**

P02 可以冻结一个不含卡牌语义的通用效果概念，以便节间战术和 P04 原型复用。每个效果必须声明：

- 来源与事实理由；
- 目标球队、球员或行为场景；
- 被修改的明确参数；
- 加法或乘法方式；
- 从哪个 `controlBoundary` 提交、哪个 `segmentIndex` 开始生效；
- 持续到若干球权、当前节末或被替换；
- 同键叠加上限和覆盖优先级。

P02 初始只由基础战术和对手策略产生效果，不出现 `Card`、牌库、费用、抽牌、英雄或特殊牌字段。P04 若验证卡牌，只能映射到同一受限效果入口，不能直接改比分、命中结果或 RNG。

P02 的叠加规则冻结为：新的基础战术替换旧基础战术；同一来源对同一参数的临时效果以新替旧；不同来源的加法效果求和后在战术层封顶 `±6`；乘法效果相乘后限制在 `0.75～1.25`；持续球权在每个已提交球权后递减。P02 本身不产生超出三轴基础战术的临时玩家效果。

P02 不提供暂停命令；篮球暂停、10 秒思考窗和卡牌换手一起在 P04/P05 验证。节间和自然死球已经足够验证最小临场调整。

## 11.4 对手 AI

P02 只需一套确定性、可解释的对手策略：

- 使用固定首发、助教轮换和基础战术档案；
- 节间检查比分、疲劳和玩家的明显防守重心；
- 落后 8 分以上可提速；
- 领先 8 分以上可降速；
- 玩家持续收缩时可提高外线权重；
- 玩家持续外扩时可提高篮下/突破权重；
- 所有变化写入原因码和赛后事实；
- 不拥有虚构手牌，不根据玩家连胜暗改命中率。

这是一套对手政策，不是难度系统。完整难度曲线属于 P06/P07。

# 12. 增量分节/球权链比赛模型

## 12.1 权威模拟单位

**[DECIDED][P02]**

统计组织单位是一次球权；权威提交单位则是“从当前 Anchor 推进到下一个合法控制边界”的比赛片段。一个统计球权可以包含多个片段，例如普通犯规死球后本方继续持球、出界后继续进攻，或进攻篮板后的再次进攻。这样每个自然死球都能让玩家/助教合法干预，而不必等整个球权结束。表现层未来可以合并已经提交的片段，但不能重新采样结果。

```text
已提交的 Match Anchor
  + 当前阵容、职责、战术、疲劳和场上默契
  + 当前片段固定随机向量
  → 解析到下一死球、球权转换或节末
  → 原子提交该片段的比分、统计、时钟和状态
  → 形成新的 Match Anchor
```

`Match Anchor` 只包含已经成立的事实：节次、时钟、比分、`possessionIndex`、该球权内的 `segmentIndex`、球权归属、场上球员、犯规、疲劳、有效战术、统计、排队换人和局部 transcript 位置。球权归属改变时才递增 `possessionIndex`；同一方死球后继续持球时只递增 `segmentIndex`。不存在整场“待播放终场比分”。

## 12.2 每个比赛片段的固定顺序

1. 读取当前五人、职责、位置适配、疲劳和场上默契；
2. 依据节奏产生回合时长，并判断转换或阵地环境；
3. 按职责、球权倾向、控球和战术选择持球者；
4. 判定压迫下失误；
5. 在合法行为中按倾向、进攻重心和防守环境选择传球、突破或出手；
6. 选择执行球员和出手区域；
7. 判定犯规、投篮和可能的助攻；
8. 未命中时判定篮板，进攻篮板则在同一统计球权的下一片段继续；
9. 写入比分、个人统计、球队统计、时钟和本片段负荷；
10. 判定死球、犯满、排队换人、节结束和加时；
11. 提交新锚点，已提交内容不可被之后命令改变。

球队得分必须由实际球权事件累积而来，禁止先抽一个球队终场分再把统计分配给球员。

死球必须由已发生的篮球事件派生：进球、出界、犯规/罚球序列、违例或节末会形成死球；活球失误和未命中后的活球篮板不会凭空形成换人窗口。随机量只可决定失误或犯规的具体合法类型，不能独立抽取“是否死球”。每个死球先提交新 Anchor，再开放命令；普通犯规或出界后若球权不变，下一片段沿用同一 `possessionIndex`。节末始终是合法换人和战术窗口。

进攻篮板后的再次进攻仍属于同一 `possessionIndex`，但进入新的 `segmentIndex`，同一片段内的重复抽签才递增 `localIndex`。每个会抽取新比赛结果的活球片段必须消耗至少 1 秒比赛时钟；零时钟片段只允许执行已确定数量的罚球、换人或战术命令，不能递归抽取新的活球事件。因此极端连续前场篮板、出界或犯规也会被节末/犯满自然终止；不得把任意 64 次或其他次数上限写成领域失败。进程 watchdog 只能报告性能/引擎故障，不能改变合法比赛结果。

## 12.3 固定随机向量

比赛开始时从全局 `match` 流派生一个局部 `matchSeed`。每个比赛片段的随机量由稳定键获得：

```text
(matchSeed, period, possessionIndex, segmentIndex, drawKind, localIndex)
```

`drawKind` 至少区分：片段时长、转换、持球者、防守动作、失误发生、失误分类、行为、出手者、投篮、进攻犯规、防守犯规、犯规类型、篮板、抢断归因、封盖归因和助攻归因。死球状态由这些已解析事件确定，不拥有独立结果抽签。

规则：

- 玩家命令和 UI 操作不消耗结果 RNG；
- 同一片段各类随机量的键不因上一分支少走一步而错位；
- 中性命令不会重抽未来；
- 阵容或战术改变时，相同随机量作用于新的概率阈值，结果变化可以归因于规则输入变化；
- cosmetic RNG 与比赛结果完全隔离；
- 同一 `MatchInput + matchSeed + 控制策略 + 命令 transcript` 必须得到同一结果 hash。

## 12.4 初始判定公式

以下是 Model B 的可运行校准起点，不是最终平衡。[CALIBRATE]

修正只结算一次，固定顺序为：先由基础能力组合得到个人执行；再扣本次行动对应的疲劳惩罚；若行动涉及错配职责，再加位置修正；满足特质场景时加特质执行点；最后加入该场景唯一一次、封顶 `±6` 的直接战术执行点。团队配合只进入传球、机会创造、协防和战术执行。下列公式中的“进攻执行/防守执行”均指完成这一步后的值，禁止在概率公式外再次乘入疲劳、位置、特质或同一战术效果。

### 直接对位

首发和每次换人都已把球员放入 PG、SG、SF、PF、C 五个场上槽位。默认直接防守者是对方同槽位球员；短人导致该槽为空时，按位置顺序中的槽位距离选择最近的在场防守者，距离相同先取较小槽位序号，再按稳定球员 ID。一次判定如需要协防者，只能从其余在场球员中按该场景执行值最高者选择，并用稳定球员 ID 打破同分。所有判定都必须保存实际候选和最终归因球员。

### 持球与传球失误

每个包含持球/传球压力或投篮干扰的防守片段，相关防守者先按第 5.7 节的二态权重选择“稳守”或“冒险”；不存在第三个“正常”状态。该动作在本片段固定为：稳守的动作压力修正 `-3`，冒险为 `+4`。[CALIBRATE]

```text
护球组织 = 0.50×控球 + 0.30×组织 + 0.20×战术理解
防守压力 = 0.55×对位外线防守 + 0.25×运动能力 + 0.20×战术理解

失误率 = clamp(
  0.13 + 0.002×(防守压力 - 护球组织)
       + 0.002×动作压力修正
       + 节奏修正
       - 0.002×团队执行修正,
  0.06,
  0.25
)

受压失误分类率 = clamp(
  0.50 + 0.04×动作压力修正 + 0.002×(防守压力 - 护球组织),
  0.10,
  0.90
)
```

节奏修正：慢 `-0.015`、平衡 `0`、快 `+0.015`。

先判定是否失误；已被判为进攻犯规的事件不再进入本分类。其余失误再用独立稳定 draw 分成 `PRESSURED_LIVE_BALL` 与 `UNFORCED_DEAD_BALL`：前者直接转换活球球权并可进入抢断归因，后者形成出界/违例死球且不记抢断。冒险动作若未制造失误，则本方在该片段后续防守执行 `-2`、对方机会质量 `+3`，表示压迫失败后的失位；稳守没有失位惩罚，但其制造失误和抢断的机会更低。上述动作修正只在本片段进入一次。

### 区域命中

区域基础命中率：篮下 `0.56`、中投 `0.39`、三分 `0.33`。

```text
篮下进攻 = 0.55×终结 + 0.20×运动能力 + 0.15×体型影响 + 0.10×战术理解
篮下防守 = 0.50×内线防守 + 0.20×运动能力 + 0.20×体型影响 + 0.10×战术理解

中投进攻 = 0.65×投射 + 0.20×终结 + 0.15×战术理解
中投防守 = 0.45×对位外线防守 + 0.25×内线防守 + 0.15×运动能力 + 0.15×战术理解

三分进攻 = 0.80×投射 + 0.20×战术理解
三分防守 = 0.65×对位外线防守 + 0.20×运动能力 + 0.15×战术理解
```

`机会质量` 是 `0～100` 的本次出手机会值，不是第 11 项球员能力：

```text
创造执行 = 0.55×创造者组织 + 0.25×创造者控球 + 0.20×创造者战术理解
团队协作指数 = clamp(50 + 5×团队执行修正, 20, 80)
空间指数 = 其他在场进攻球员的平均(0.70×投射 + 0.15×运动能力 + 0.15×战术理解)
对方协防执行 = 对方非直接对位球员的平均(0.50×外线防守 + 0.30×内线防守 + 0.20×战术理解)
               + 对方团队执行修正
协防环境 = 100 - clamp(对方协防执行, 0, 100)

机会质量 = clamp(
  0.35×创造执行 + 0.25×团队协作指数
  + 0.20×空间指数 + 0.20×协防环境
  + 机会类战术执行点,
  0,
  100
)
```

最后一次传球直接形成出手时，创造者是传球者；否则创造者是出手者本人。空间指数排除出手者，协防环境排除直接对位者，避免把同一名防守者在机会质量和区域防守中重复计算；短人时按实际在场候选平均，集合为空则取中性值 `50`。机会类战术执行点只表达明确让出的空间，例如外扩压迫对篮下 `+3`、收缩禁区对三分 `+3`，单轴仍限制在 `±6`。

```text
命中率 = clamp(
  区域基础值
  + 0.0025×(区域进攻执行 - 区域防守执行)
  + 0.0015×(机会质量 - 50),
  区域下限,
  区域上限
)
```

候选上下限：篮下 `0.25～0.80`、中投 `0.15～0.65`、三分 `0.10～0.60`。特质、位置、疲劳和直接战术修正已经进入区域执行，不再另加“场景执行修正”，也不把 `+6` 误当作 `+600%` 命中率。

罚球：[CALIBRATE]

```text
罚球命中率 = clamp(
  0.75 + 0.003×(投射 - 50) - 0.002×疲劳执行惩罚,
  0.45,
  0.95
)
```

罚球不受场上默契影响。

### 前场篮板

```text
个人篮板执行 = 0.60×篮板 + 0.20×体型影响 + 0.20×运动能力

前场篮板率 = clamp(
  0.27 + 0.0025×(进攻篮板执行 - 防守篮板执行),
  0.12,
  0.45
)
```

前场篮板倾向只决定哪些进攻球员参加冲抢以及候选权重；它不直接提高争抢成功率。过滤参赛者后，双方按倾向权重选择一名明确争抢者，使用其个人篮板执行比较；疲劳、位置和“篮板嗅觉”只在该执行值中进入一次。收缩禁区的防守篮板 `+2` 作为防守争抢者的直接战术执行点进入，P02 没有另一个未定义的“战术修正”。

### 犯规、抢断、封盖与助攻

以下判定都在事件发生时完成并写入同一比赛片段，不得在终场后补抽统计。[CALIBRATE]

**犯规。**防守冒险倾向沿用本片段已经选择的稳守或冒险动作；倾向不直接进入成功率。防守犯规候选默认是直接对位者，明确发生协防时改为该协防者。

```text
防守控制 = 0.55×相关区域防守 + 0.25×战术理解 + 0.20×运动能力

进攻对抗（篮下/突破） = 0.50×终结 + 0.25×运动能力 + 0.15×体型影响 + 0.10×控球
进攻对抗（中投/三分） = 0.60×投射 + 0.20×控球 + 0.20×战术理解

防守犯规率 = clamp(
  场景基础犯规率 + 0.0015×(进攻对抗 - 防守控制) + 动作风险修正,
  0.01,
  0.25
)
```

场景基础犯规率：持球压迫 `0.04`、中投/三分干扰 `0.05`、篮下/突破 `0.10`；动作风险修正：稳守 `-0.015`、冒险 `+0.025`。突破动作先独立检查进攻犯规：

```text
进攻犯规率 = clamp(
  0.02 + 0.001×(防守控制 - (0.50×控球 + 0.30×运动能力 + 0.20×战术理解)),
  0.005,
  0.08
)
```

进攻犯规成立时立即失去球权并给进攻者记个人犯规，不再检查同一动作的防守犯规。防守犯规发生在投篮动作时按投篮结果结算 2/3 次罚球或加罚 1 次；非投篮防守犯规形成死球且进攻方保留球权。P02 不模拟球队犯规奖励。

**抢断。**只有已分类为 `PRESSURED_LIVE_BALL` 的失误才有抢断归因候选；默认候选是该持球者的直接防守者。归因失败时仍保留受压活球失误，但标为无抢断归因。

```text
抢断执行 = 0.60×外线防守 + 0.25×运动能力 + 0.15×战术理解 + 动作压力修正
护球执行 = 0.55×控球 + 0.25×组织 + 0.20×战术理解
抢断归因率 = clamp(0.35 + 0.003×(抢断执行 - 护球执行), 0.10, 0.75)
```

**封盖。**只在篮下或中投已经判定未命中后分类，不再次改变命中结果。候选是直接防守者，以及实际进入协防的至多一名球员；取封盖执行更高者。

```text
封盖执行 = 0.55×内线防守 + 0.25×体型影响 + 0.20×运动能力
出手保护（篮下） = 0.50×终结 + 0.25×运动能力 + 0.15×体型影响 + 0.10×战术理解
出手保护（中投） = 0.60×投射 + 0.20×控球 + 0.20×战术理解
封盖归因率 = clamp(0.08 + 0.002×(封盖执行 - 出手保护), 0.01, 0.25)
```

**助攻。**候选只能是同一球权内最后一次合法传球的传球者；传球后若射手又完成突破、背打或其他自主创造动作，则无助攻候选。只有随后投篮命中才检查一次归因。

```text
助攻执行 = 0.60×传球者组织 + 0.20×传球者战术理解 + 0.20×团队协作指数
自主创造 = 0.45×射手控球 + 0.35×区域主能力 + 0.20×射手运动能力
助攻归因率 = clamp(0.55 + 0.0025×(助攻执行 - 自主创造), 0.15, 0.90)
```

区域主能力在篮下为终结，在中投/三分为投射；无候选或归因失败则不记助攻。每次命中最多 1 次助攻，每次失误最多 1 次抢断，每次未命中最多 1 次封盖。

助攻、抢断、封盖和犯规必须来自同一球权事实，不可在赛后另行随机分配。实现可在 P02-003 中校准系数，但不得改变“倾向选行为、能力判执行、实际事件累积统计”的结构。

### 统计归因的简化规则

- 只有一次传球在同一球权中直接创造已命中投篮机会时才可能记助攻；组织和团队执行决定是否成立；
- 抢断只能来自由明确防守者施压造成的失误；防守冒险提高抢断机会，也同步提高失位和犯规风险；
- 盖帽只能来自篮下/中距离投篮的明确干扰者，未命中后的球权仍按实际篮板处理；
- P02 只模拟普通个人犯规、投篮犯规和进攻犯规，不模拟技术犯规、违体犯规、教练挑战或复杂球队犯规奖励；
- 投篮犯规按出手区域产生 2 或 3 次罚球；进球且犯规时追加 1 次罚球；
- 每个统计都能回指产生它的球权事件和球员，禁止终场补随机数凑 box score。

## 12.5 加时、犯满和人数不足

- 正式赛、友谊赛平局后进行 5 分钟加时，直至分出胜负；
- 队内赛允许平局；
- 第 5 次个人犯规后强制离场；
- 无可替换球员时允许以 4、3 或 2 人继续；少于 2 名合资格球员时以 `FORFEIT_INSUFFICIENT_PLAYERS` 结束；
- 规则性失败时，对方被记为胜者；终止前已经产生的比分和个人/球队统计原样保留，并在结果中同时记录 `terminationReason` 和终止时比分。正式胜负按规则性胜者结算，不伪造 20:0 或补写球员得分；队内赛只提前结束，不进入正式记录；
- 加时按 5 分钟重复直到分出胜负。实现可以有进程 watchdog，但触发即是必须修复的引擎不变量错误，不是可重试领域结果、抽签胜负或常规用户路径；工作副本不得提交，Gate 的全部固定 seed 必须零触发。

## 12.6 比赛局部状态与全局周事务

P01 冻结的不变量禁止把尚未结算周的比赛或预算记录提前写入全局状态。因此 P02 不能把训练结算、比赛完成和周推进拆成互相独立的全局提交。

冻结事务语义：

1. 全局可以保存周计划、友谊赛选择、名单、首发和赛前战术，但这些只是“计划”；
2. 开始结算运营周时，克隆全局 state 与相关 RNG；
3. 在工作副本上先结算训练/活动，再建立 `MatchSession`；
4. 完整执教期间只修改比赛局部会话和工作副本；
5. 比赛结束后，以一个 `COMPLETE_OPERATION_WEEK` 事务同时提交训练、比赛、疲劳、经费、声誉、成长、档案增量并推进日历；
6. 非法局部命令只拒绝该命令；当前 Anchor、局部 RNG 和 transcript 均不变化，比赛继续；
7. 玩家明确退出本场、进程异常或会话不变量损坏时，才丢弃整个工作副本并回到赛前；全局 state、revision、RNG、账本和审计日志均不变化；
8. 考试周通过独立的无球员活动推进事务处理；推进到下一周时，在同一事务内应用“进入周”的自然恢复。

比赛局部 transcript 使用局部序号和时钟，主命令审计只保存最终结果引用、transcript hash 和周完成事件，不把数百个球权伪装成全局 DomainEvent。

## 12.7 一份实际结果，多种表现

`step` 每次推进到下一个合法控制边界；`runToEnd` 只是连续调用相同的 `step`，并在每个边界按当前控制策略执行命令或继续。因此：

- 快速结算消费实际球权结果但不播放；
- 调试文本按同一事件输出；
- 未来拨片、关键时刻和 2D 只能读取这些已提交事件；
- 表现层无权重算比分或球员统计；
- 在相同控制策略和命令 transcript 下，逐步推进与一次跑完必须完全一致。

完整执教无操作与快速结算**不要求**结果相同，因为前者没有主动助教轮换，后者有；应比较的是各自模式内部的可重放性。

# 13. 比赛统计、解释与玩家学习

## 13.1 P02 权威统计下限

球队与球员统计由球权事件累计。每名球员至少记录：

- 出场分钟；
- 得分；
- 投篮命中/出手；
- 三分命中/出手；
- 罚球命中/出手；
- 进攻篮板、防守篮板；
- 助攻；
- 抢断；
- 盖帽；
- 失误；
- 犯规。

比赛至少记录：

- 类型、记录范围和对手；
- 每节及加时比分；
- 名单与首发；
- 换人、强制替换和战术变更；
- 时间加权平均场上默契；
- 训练前、赛前、赛后疲劳变化；
- 规则版本、内容版本、seed 引用和 transcript hash；
- 可验证的解释事实。

完整 lineup stints、usage、shot chart、plus-minus、反事实胜率和卡牌窗口不是 P02 权威持久字段；需要时可由事件推导或在 P08 扩展。

## 13.2 分类记录

| 数据                 | 正式赛 |     友谊赛 |   队内赛 |
| -------------------- | -----: | ---------: | -------: |
| 比分与基础 box score |   完整 |       完整 | 摘要即可 |
| 球队正式胜负         |     是 |         否 |       否 |
| 球员正式生涯         |     是 |         否 |       否 |
| 友谊赛独立档案       |     否 |         是 |       否 |
| 训练观察/成长        |     是 |         是 |       是 |
| 声誉                 | 按结果 | 仅首次条件 |       无 |

## 13.3 默认结果页

普通玩家首先看到：

- 最终比分和每节比分；
- 按第 14.2 节显示型贡献分排序的本场 3 名主要球员；
- 得分、篮板、助攻和出场时间；
- 本周能力升级、实战 XP 和默契变化；
- 训练疲劳与比赛疲劳；
- 经费与声誉变化；
- 2～3 条最有价值的事实解释。

队内赛默认显示“观察摘要”，例如替补表现、疲劳风险和能力使用，不强调胜负。

## 13.4 可选明细

明细页或调试输出可展示：

- 各区域出手与命中；
- 失误、前场篮板和罚球来源；
- 换人前后实际阵容阶段；
- 场上默契随换人的变化；
- 战术生效期间实际行为分布；
- 位置错配和疲劳实际参与了多少次判定；
- 对手策略变化及原因码。

## 13.5 解释边界

解释只能陈述：

1. **实际事实**：发生了什么；
2. **规则作用**：某输入改变了哪个权重或判定；
3. **可观察关联**：该窗口内实际统计怎样。

允许：

> 第三节改为收缩防守后，对手 7 次篮下出手命中 2 次，同时获得 4 次外线空位机会。

> 本场平均场上默契 68，团队执行修正平均为 +2.2；它参与了 11 次传球衔接和 8 次协防判定。

禁止：

> “收缩防守让你赢下了比赛。”

除非规则直接定义因果，否则不能把一次胜负归功于单个战术，也不能由 LLM 补写不存在的分析。

## 13.6 玩家如何从反馈中学习

每场结算回答三个固定问题：

1. **准备是否合适？**训练强度和疲劳怎样影响了可用阵容；
2. **谁适合什么职责？**实际持球、出手、组织、防守和篮板分布是否符合角色；
3. **战术产生了什么取舍？**实际增加了哪些机会，同时让出了什么。

系统不直接告诉玩家下场照抄某个答案，而是让其据此决定下一周训练、恢复、名单和战术。

# 14. 年级推进、毕业与最小档案

## 14.1 年度顺序

**[DECIDED][P02]**

第 40、80、120 周在进入该考试/收束周时已经完成自然恢复；完成该周时按固定顺序：

1. 完成本周时间结算；
2. 高一升高二、高二升高三；高三先生成不可变的最小生涯档案，再从活跃名单移出；
3. 学校和球队的已完成学年计数各增加 1；
4. 结算且仅结算一次年度拨款；
5. 第三学年结束时把状态置为三年完成，且恰好结算 120 周。

第 2 步以结算开始时的年级快照对每名活跃球员只分支一次：快照为高一/高二者只升一级，快照为高三者才毕业；不得让本次刚升入高三的球员在同一次循环再次毕业。

这是 P02 对事件顺序的版本化决定，沿用 P01 `settleSchoolYear` 的生命周期先于拨款语义，但不把具体旧函数或旧 Schema 冻结为新接口。

P02 不生成新生，因此只要求固定夹具能够合法完成三年；人数可持续性属于 P03。

P02 新游戏夹具必须保证：每个仍有运营周的学年开始时至少有 12 名活跃球员，每个队内赛周至少有 10 名活跃球员。第三学年第 120 周后的毕业可以把活跃人数降到该阈值以下，因为此后没有 P02 比赛；任何更长期补员规则仍属于 P03。

## 14.2 P02 最小毕业档案

每名毕业球员保存：

- 身份、角色内容引用、入队和毕业日期；
- 最终年级、星级、位置、10 项能力、体型代理、特质；
- 正式生涯比赛数、分钟、得分、篮板、助攻、抢断、盖帽、失误和犯规；
- 友谊赛统计单独摘要；
- 队内赛只保留成长/观察总次数，不计正式比赛；
- 正式赛单场得分、篮板、助攻最高值；没有正式出场时为 `null`，不伪造 0 分纪录；友谊赛最高值如保留，只能进入独立友谊赛摘要；
- 可选的一场代表正式比赛 ID；没有正式出场时为 `null`；
- 效力期间球队正式成绩；
- 最终个人默契和毕业时的玩家培养摘要。

用于结果页排序的显示型比赛贡献分为：[CALIBRATE]

```text
贡献分 = 得分 + 1.2×篮板 + 1.5×助攻 + 2×(抢断+盖帽)
       - (投篮出手-投篮命中) - 失误 - 0.5×犯规
```

贡献分不参与比赛、成长、声誉或星级，只用于选择结果页主要球员。代表比赛取正式赛贡献分最高的一场；同分按得分、篮板+助攻、更晚日期、稳定比赛 ID 依次打破；没有正式出场则保持 `null`。P02 不生成主观叙事。

## 14.3 延期的档案表现

- 毕业纪念页、相册、完整校史浏览和奖项 UI：P07；
- 名人堂、学校传统、徽章传承和 5★/6★传奇：P09；
- LLM 生成的回忆、对话和人物总结：P10，且只能读取结构化事实。

经费、球队声誉和正式球队历史属于学校资产，不因一届球员毕业而清空。

## 15.3 版本和内容兼容

**[P02]**

P01 存档是工程证据夹具，不是公开发行玩家存档。P02 应：

- 提升 Engine Version、Save Schema Version 和规则内容包版本；
- P02 新游戏使用新的 3★/4★内容夹具；
- 对 P01 存档返回稳定、明确的“不支持旧玩法版本”，不静默把 2★、四属性或旧状态重解释为新语义；
- 保留 P01 fixture、golden replay 和 Model A 回归适配器；
- 不修改 P01 历史 evidence 或 manifest；
- 加载时核对所有会影响规则的内容 hash；
- 重放身份必须包含 state、RNG、engine/schema 版本、内容 hash 和比赛 transcript hash。

表现资源和 cosmetic 内容不影响比赛 hash；角色能力、倾向、特质和训练表属于规则内容，必须纳入兼容校验。

P01 回归资产必须与 P02 生产模型隔离：建立只供 fixture、golden replay 和 Model A 测试使用的 `LegacyP01` 类型/Schema/适配层，Model A 只依赖该层；P02 的公开 Save Schema 只接受 V2，不使用 V1/V2 联合类型，也不为了让旧 `model-a.ts` 编译而把四属性和旧 condition 留在新 `Player` 中。P01 历史 evidence 保持不可变，legacy 测试是否运行不代表 P01 存档可被 P02 加载。

### 权威数值精度

- 能力、经费和声誉保存为整数；比赛时钟和出场时间保存为整数秒，分钟只作显示派生；
- XP、疲劳和个人默契使用千分之一点的定点值，权威边界采用十进制四舍五入到 3 位；
- 训练/活动结算、每个已提交比赛时间片和赛后成长各是一次舍入边界；同一边界内用未舍入中间值，不能因 UI 展示提前舍入；
- 概率和执行值是瞬时计算量，不直接写入存档；结果事件和持久数值才进入 hash。

这样 `step` 与 `runToEnd`、保存重载和不同展示路径不会因浮点尾数产生不同权威状态。

## 15.4 状态变化的原子边界

| 操作                   |           可以立即写入全局计划 |         可以立即产生玩法结算 |
| ---------------------- | -----------------------------: | ---------------------------: |

# 17. 验证计划与 Gate

## 17.1 规则不变量

P02 Gate 至少证明：

- 三年恰好 120 日历周、96 运营周、24 考试/收束周；
- 96 个运营周各恰好一个比赛槽，24 个考试周为零；
- 固定占位赛程恰好 24 场正式赛，其余 72 场为友谊赛或队内赛；
- 考试周零训练、零恢复计划、零活动、零比赛、零 XP 和零默契经验；
- 三类比赛不互相污染正式胜负、正式生涯、友谊档案和声誉；
- 球队总分等于球员得分合计，每节/加时合计等于终场比分；
- 球员得分必须等于 `2×两分命中 + 3×三分命中 + 罚球命中`，球队对应统计为球员统计之和；
- `Σ球员出场分钟 = Σ各时间区间(该队实际在场人数 × 区间时长)`；正常无短人时等于 `5 × (40 分钟 + 加时分钟)`，短人阶段按实际人数核对；
- 命中不大于出手，三分命中不大于三分出手，犯满球员不再进入后续球权；
- 同一输入、内容 hash、seed、控制策略和 transcript 得到同一结果 hash；
- 同一控制策略下，逐步 `step` 与连续 `runToEnd` 结果一致；
- 后续命令不能修改已提交球权；中性命令不能改变未发生随机量；
- 非法局部命令只被拒绝且不改变 Match Anchor、局部 RNG 或 transcript；整场中止、会话损坏和事务失败不污染全局 state、RNG、revision、日志或账本；
- 每个仍有运营周的学年至少 12 名活跃球员，每个队内赛周至少 10 名；
- 规则判定完全不依赖 LLM、网络或表现帧率。

## 17.2 五个基础方向性场景

每个场景使用至少 32 个固定配对 seed；同一配对只改变被测变量。[CALIBRATE]

| 场景               | 必须观察到的方向                             | 不要求             |
| ------------------ | -------------------------------------------- | ------------------ |
| 明显强弱队         | 强队平均分差为正且多数 seed 获胜             | 不冻结最终胜率曲线 |
| 高疲劳 vs 充分恢复 | 高疲劳队执行效率、末节表现和胜率更低         | 不模拟伤病         |
| 正常位置 vs 错配   | 错配队战术执行更差、相关失误/防守问题更多    | 不禁止错配         |
| 战术适配 vs 不适配 | 目标区域的机会或防守指标按规则方向变化       | 不保证适配战术必胜 |
| 浅轮换 vs 深轮换   | 深轮换末节疲劳更低；浅轮换核心早段使用更集中 | 不预设哪种永远更优 |

## 17.3 增补场景

- 同能力、不同倾向产生不同持球、传球和出手分布；
- 同阵容、不同个人默契产生不同团队执行；
- 换人后场上默契按职责权重即时重算；
- 完整执教无主动换人仍能完成比赛；
- 快速结算按预设产生稳定助教轮换；
- 犯满时固定兜底生效，极端人数不足返回受控结果；
- 加时继续逐时间片增加疲劳，外扩压迫的额外负荷只在防守时间片生效；
- 队内赛确定性分组、全员观察和低负荷正确；
- 资金不足的友谊邀请完全失败，默认队内赛仍保留；
- 重复战胜同一友谊对手不重复刷声誉；
- 战术改变只影响之后球权，不改变之前统计；
- 同一战术重复提交不叠加效果，也不改变局部 RNG 或 transcript；
- cosmetic RNG 改变不影响比分；
- P01 legacy fixture 仍可完成原有回归，但不被新 P02 状态静默读取。

## 17.4 三年与性能验证

- 使用确定性自动政策完成 1,000 次三年快速模拟；
- 0 非法终态、0 重放不一致、0 分类账污染；
- 所有年度拨款、毕业和档案发生在正确周；
- 快速结算性能目标在首个可运行 Model B 切片建立基准后登记，不沿用 Model A 的速度冒充 Model B SLA；
- 每个实现切片提交时即运行对应事务、存档和确定性测试；最终 Gate 切片只汇总证据，不能把验证全部拖到最后。

## 17.5 低惩罚检查

每个机制通过 Gate 前必须回答：

- 选择错误是否会永久毁掉球员？
- 是否存在无提示硬锁？
- 玩家是否可能因随机性永久失去核心？
- 低经费时是否仍有免费队内赛和恢复路径？
- 不研究公式能否依靠推荐和基础结果继续？
- 系统是否暗中根据连胜、领先或是否付费改变结果？

任一答案违背第 2 章原则时，不能以“之后再平衡”放行。
