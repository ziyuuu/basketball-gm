## 1. 产品语义与兼容映射

比赛内统一使用“单场体力”表达：范围 `0～100`，越高越充足，每场所有参赛球员都从 `100` 开始。训练负荷、赛程状态或旧输入中的赛前疲劳不换算为开场体力，也不形成另一套比赛能力惩罚。

为避免重开 P02-002 已冻结 Schema，现有协议字段按下表兼容：

| 既有字段                           | P02-003 修订后语义                                          |
| ---------------------------------- | ----------------------------------------------------------- |
| `MatchPlayerSnapshot.fatigueMilli` | 保留为兼容字段；不得作为 Model B 开场体力或比赛能力惩罚输入 |
| `MatchAnchor.fatigueMilliByPlayer` | 本场已消耗体力，开场统一为 `0`，范围 `0～100000`            |
| 玩家可见剩余体力                   | `energyMilli = 100000 - fatigueMilliByPlayer[playerId]`     |

Model B session 必须以全体 `fatigueMilliByPlayer = 0` 建立首个 Anchor。相同 MatchInput 只改变赛前 `fatigueMilli` 时，比赛开场体力和后续比赛结果不得改变。P02-004 建立正式 V2 球员状态时，应把赛前训练状态与单场体力分名，不能继续复用一个产品字段表达两者。

## 2. 单场体力消耗

唯一结构为：

```text
本次体力消耗 = 在场时间基础消耗 + 实际行为追加消耗
```

### 2.1 在场时间基础消耗

- 每个已提交的比赛时间片，场上十名球员按实际流逝时间承担相同的低强度基础消耗；
- 基础消耗不乘比赛节奏系数或全队防守策略系数；
- 快节奏只因单位时间内实际行为更多而产生更多行为追加消耗，不能再次放大基础消耗；
- 替补席球员不承担场上基础消耗。

### 2.2 实际行为追加消耗

- 只记到该行为的实际参与者，包括发起者、直接对位者和实际选中的空切、追防、协防、扑防、封盖等参与者；
- 行为 registry 必须声明消耗强度档和参与者角色；
- 主动进攻按行为自身强度消耗；
- 只维持位置、跟随或顶住的被动防守，比对应主动进攻低一个强度档；
- 紧逼、追防、协防、扑防、封盖等主动防守按自身行为强度消耗；
- 未成为该行为参与者的其他场上球员只有基础消耗。

具体基础消耗、强度档数值和最低档边界均为 `[CALIBRATE]`，但上述记账关系不可通过调参改变。

### 2.3 耐力

`stamina` 同时降低基础消耗和行为追加消耗，但不提高体力上限、开场体力或任何恢复速度。`strength` 不减免体力消耗。耐力换算曲线为 `[CALIBRATE]`。

## 3. 体力对比赛能力的影响

根据剩余 `energyMilli` 计算唯一档位惩罚：

| 剩余体力  | 能力惩罚 |
| --------- | -------: |
| `80～100` |      `0` |
| `70～79`  |     `-5` |
| `60～69`  |    `-10` |
| `50～59`  |    `-15` |
| `40～49`  |    `-20` |
| `30～39`  |    `-25` |
| `0～29`   |    `-30` |

定点边界按剩余体力的整数点向下取整后查表。例如 `79.999` 属于 `79` 档并扣 `5`；`80.000` 不扣。惩罚在 `-30` 封顶。

惩罚统一作用于参与比赛判定的十项非耐力能力：

- `finishing`；
- `shooting`；
- `ballHandling`；
- `playmaking`；
- `perimeterDefense`；
- `interiorDefense`；
- `rebounding`；
- `athleticism`；
- `tacticalUnderstanding`；
- `strength`。

`stamina` 自身不扣，避免循环削弱；`heightCm`、`wingspanCm` 等不可训练身体条件不扣；有效能力最低为 `0`。惩罚只作用于本场派生有效能力，不修改球员基础能力或成长值。

行为选择与结果判定都读取派生有效能力，但不得新增疲劳保护模式、高强度行为强制降权或独立疲劳状态机。

## 4. 单场恢复

- 替补席球员按实际流逝的比赛时间缓慢恢复，恢复速度统一且不受耐力影响；
- 普通节间全体参赛球员获得少量恢复；
- 中场恢复高于普通节间；
- 恢复不超过 `100`，节间和中场均不直接回满；
- 常规时间体力延续到加时，加时前按普通节间恢复；
- 暂停只服务抽取/调整战术卡，不恢复体力；P02-003 不因此提前实现卡牌系统。

替补席、普通节间和中场恢复量均为 `[CALIBRATE]`，但恢复来源及相对关系不可改变。

## 5. 正常位置与唯一强制错位例外

### 5.1 正常规则

- 球员只有一个产品主位置；
- 玩家不能主动把球员安排到其他位置；
- 正常首发与轮换必须优先使用对应主位置球员；
- 不设计副位置、位置熟练度、主动错位、跨位置适配或特殊豁免。

为保持 P02-002/P02-003 已冻结快照兼容，既有 `secondaryPosition` 字段可以暂时保留在协议中，但它不再拥有产品语义，不得参与位置合法性、轮换排序、行为权重或惩罚减免。P02-004 的正式 V2 球员 Schema 不再建立副位置系统。

### 5.2 人员不足时的强制错位

只有当轮换、犯满、资格失效或名单覆盖不足导致某位置没有可用主位置球员、系统无法补齐合法五人阵容时，才允许确定性强制错位：

1. 先按主位置寻找可用替代者；
2. 无主位置候选时，按公开、稳定的候选排序选择其他位置球员；
3. 强制错位球员承受统一的比赛能力扣减；
4. 扣减作用于除 `stamina` 和不可训练身体条件外的全部比赛能力，与体力惩罚相加后再把有效能力下限截为 `0`；
5. 一旦对应主位置球员重新可用，后续轮换恢复正常位置；
6. Event/Fact 或结构化原因码必须记录强制错位及触发原因，使 replay 和赛后说明可回指。

强制错位的统一扣减值为 `[CALIBRATE]`。不得建立副位置轻罚、不同位置组合表或玩家主动错位入口。

## 6. 对旧条款的精确覆盖

以下旧条款作废：

| 旧条款                                                       | 修订结论                                               |
| ------------------------------------------------------------ | ------------------------------------------------------ |
| 赛前疲劳直接进入比赛并影响开场能力                           | 每场从 `100` 体力开始；赛前状态不进入 Model B 单场体力 |
| 疲劳越高越差的连续公式 `clamp((fatigue - 30) × 0.20, 0, 14)` | 改为第 3 节体力档位，最多 `-30`                        |
| 组织/战术理解只承受半额疲劳惩罚                              | 所有非耐力比赛能力统一扣减                             |
| 基础时间负荷乘节奏或全队防守策略系数                         | 基础只看时间；策略差异由实际行为追加消耗体现           |
| 主位置加最多一个副位置                                       | 产品只保留主位置；兼容字段无产品语义                   |
| 玩家可主动任意错位                                           | 禁止；只允许无人可补时的系统强制错位                   |
| 副位置 `-3`、其他位置 `-8`                                   | 改为强制错位单一公开扣减值 `[CALIBRATE]`               |
| 暂停产生现实休息恢复                                         | 暂停不恢复体力                                         |

P02-003 v2.9-R1 的十一能力、显式 `strength`、不可训练身高/臂展继续有效。`strength` 受体力和强制错位的普通能力惩罚，但不减免体力消耗。

## 8. 验收矩阵

最低必须覆盖：

- `fatigueMilli` 输入为 `0/10/80/100` 时，Model B 首个 Anchor 都是全员本场消耗 `0`；
- `energy=80` 无惩罚、`79.999` 为 `-5`，并覆盖 `70/69.999`、`60/59.999`、`50/49.999`、`40/39.999`、`30/29.999` 和 `0`；
- `strength` 受罚，`stamina/heightCm/wingspanCm` 不受罚；
- 相同时间的基础消耗不因慢/快节奏改变；
- 实际高强度行为参与者比未参与者多消耗，主动防守按自身档、被动防守低一档；
- 高耐力在相同时间和相同行为下消耗更少，但开场、上限和恢复相同；
- 替补席随时间恢复，中场恢复大于普通节间，暂停恢复恒为 `0`；
- 正常首发/轮换拒绝主动错位并忽略 `secondaryPosition`；
- 无对应主位置候选时确定性强制错位，统一扣减只结算一次；主位置候选恢复可用后回归正常轮换；
- 以上全部在 `step/runToEnd/replay` 保持身份一致。

未冻结的消耗、恢复、耐力曲线、轮换阈值和强制错位扣减，必须通过预注册 fixture 校准，不能由实现线程提升为永久产品规则。
